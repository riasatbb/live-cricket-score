1

Create a Firebase project

Go to console.firebase.google.com, open a project on the free plan, then go to Build → Realtime Database → Create Database (Start in test mode). The live score syncs at liveMatch, every finished match is archived permanently under matchHistory, and history deletes are made final everywhere by tombstones under matchHistoryDeleted. All three paths stay publicly readable (guests and viewers can watch without logging in), but writes require the owner: publish these Rules in Realtime Database → Rules — see step 5 below for exactly what they enforce and when they take effect.

2

Turn on Google sign-in

In the Firebase Console go to Build → Authentication → Sign-in method and enable Google. Then open Authentication → Settings → Authorized domains and make sure the domain this page is hosted on (e.g. riasatbb.github.io) is in the list — Google sign-in is refused from any domain that is not listed. The "Sign in with Google" button in the Scorer Console then works: whoever signs in and creates a match or tournament becomes its owner/admin, and only that account can score, edit or delete it. Everyone else — signed in or not — is read-only for it, and guests can watch everything without logging in.

3

Add a web app and copy the config

Project Settings → Add app → Web (</>) — you will get an object called firebaseConfig (with apiKey, databaseURL, and more). Copy it and paste it into the box below.

4

Connect here

Paste the config below and tap “Connect to Firebase” — this page then links to the live database. Every ball from the scorer goes to the database, and anyone with the scoreboard or overlay open receives it instantly.

5

Two separate links — one for you, one for viewers

This page is hosted on GitHub Pages, so the same address with a different ending opens a different page. Your control link ends in …/?view=scorer and opens the Scorer Console — score only from there, and keep that link to yourself. The viewer link ends in …/?view=live — share that one with everyone: viewers land on the Live Matches list, tap a match, and watch its Public Scoreboard read-only, with no controls on the page. The OBS overlay link ends in …/?view=overlay. All three read the same Firebase data.

6

Publish the owner Rules (server-side lock)

The app already enforces ownership on screen — guests and other accounts see everything read-only. For the database itself to enforce it too, publish these Rules in Realtime Database → Rules. They keep every path publicly readable, but a write is accepted only from a signed-in account that owns the record: the live match (and the tournament inside it) can be written only by the account whose UID is stored in its ownerUid — or claimed by a signed-in account when it has no owner yet — each history entry can be written or deleted only by its owner, and delete tombstones can be written by any signed-in account (the app only writes one while deleting its owner's match):
{ "rules": { "liveMatch": { ".read": true, ".write": "auth != null && ( !data.exists() || !data.child('ownerUid').exists() || data.child('ownerUid').val() == '' || data.child('ownerUid').val() == auth.uid ) && newData.child('ownerUid').val() == auth.uid" }, "matchHistory": { ".read": true, "$matchId": { ".write": "auth != null && ( !data.exists() || !data.child('ownerUid').exists() || data.child('ownerUid').val() == '' || data.child('ownerUid').val() == auth.uid )" } }, "matchHistoryDeleted": { ".read": true, "$matchId": { ".write": "auth != null" } } } }

⚠️ Honest security note: ownership is enforced in this app right away — the scoring pad, editors and delete buttons lock for everyone except the signed-in owner, and guests are view-only. Server-side enforcement starts only when the step-6 Rules above are published in the Firebase Console: until then the database itself still accepts public writes, so someone writing to it directly (outside this app) could still change data. Once those Rules are published, keep scoring from the account that owns the match — writes from any other account, signed in or not, are rejected by Firebase itself.
Firebase auto-connects with the built-in default config — no pasting needed. Paste a different config only to use another project.
